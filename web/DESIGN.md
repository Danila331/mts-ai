# Веб-стенд и виджет ИИ-консультанта МТС EnergyTool

Цель — показать жюри не только ответы бота, но и **почему** он так ответил, и доказать, что решение
встраивается в любой сайт одной строкой `<script>`.

## Состав

```
                 ┌──────────────────────── web/ (Next.js 16, TypeScript, shadcn/ui) ─────────────────────────┐
 жюри ──────────▶│ /playground  чат + сессии + отладка    /kb  база знаний     /widget  встраивание и превью │
                 │ /embed       чат внутри iframe виджета (без отладки)                                     │
 сайт МТС ──────▶│ /widget.js   загрузчик виджета (TypeScript → esbuild, без зависимостей)                  │
 (любой домен)   │ /api/*       прокси на Go-API (тот же origin — без CORS для фронта; токен знает только сервер)│
                 └───────────────────────────────────────────┬──────────────────────────────────────────────┘
                                                             ▼
                          backend/ — Go-API: заявки, оценки, журнал ответов (Postgres), пределы частоты
                          SSE: stage(retrieval) → stage(generation) → answer → done (поток ядра как есть)
                                                             ▼
                          scripts/core_api.py — Python-ядро, общий energybot.Consultant (режим chat)
```

- Ядро не дублируется: `scripts/core_api.py` наследует `Consultant` и только **перехватывает** выдачу поиска
  и промпт, чтобы отдать их отладочной панели. Ответ формируется ровно той же цепочкой, что и в `solution.py`.
- Go-API (`backend/`) — публичная часть: принимает запросы фронта, пересылает поток ядра, хранит заявки,
  оценки и журнал ответов в Postgres. Ядро — внутренняя служба: наружу не смотрит.
  Деплой: фронт — Vercel, API, ядро и база — Railway ([docs/deploy.md](../docs/deploy.md)).
- Стенд сайта МТС (`web/scripts/stand.mjs`) раздаёт сохранённую копию energytool.mts.ru с другого порта
  (другой origin — честная проверка встраивания), вырезает счётчики аналитики и подставляет тег виджета.
  Копия сайта в репозиторий не кладётся.

## Экраны

### 1. Стенд `/playground` — три колонки

| Сессии (240px) | Чат (гибкая) | Отладка (≈40%, тянется) |
|---|---|---|
| «Новый диалог», список с поиском, переименование, удаление, экспорт JSON/Markdown | Стартовые вопросы по продуктам; ответы с номерами источников после предложений; превью раздела при наведении; 👍/👎 с комментарием; копировать; «Ответить заново»; «Передать менеджеру» | Вкладки для выбранного ответа: **Опора**, **Поиск**, **Контекст**, **Промпт**, **Проверка**, **JSON** |

Шапка: статус API (модель, эмбеддинги, реранкер, размер базы), переключатель режима
**Чат** (бот может предложить заявку) / **Автопроверка** (как на платформе: без заявки и контактов).

Вкладки отладки:

- **Опора** — каждое предложение ответа → разделы базы, на которые оно опирается (пересечение основ слов +
  совпадение чисел). Числа без опоры подсвечены красным. Это эвристика стенда, подписана как эвристика.
- **Поиск** — запросы (лексический/смысловой), топ-30 кандидатов: место, скор, ступень (bm25/rrf/rerank),
  попал ли в контекст; клик открывает раздел.
- **Контекст** — что именно ушло модели: документы целиком, отдельные фрагменты, справочник; размер в символах.
- **Промпт** — system/user как есть, с поиском по тексту и копированием.
- **Проверка** — срабатывания `guard`: числа не из базы, перезапрос, вырезанные предложения, длина; тайминги
  этапов полосой (поиск → генерация → проверка).
- **JSON** — сырой ответ API для разработчиков.

### 2. База знаний `/kb`

Дерево: группа (`00-reference`, `10-energy`, `20-products`) → документ → разделы. Справа — документ, нарезанный
**теми же фрагментами, что видит модель** (id = sha1 из `kb.py`). У каждого раздела якорь `#c-<id>`, бейджи
«справочник» / «ограничения» и ссылки на связанные документы. Ссылка `/kb?chunk=<id>` открывает документ,
прокручивает к разделу и подсвечивает его — так работают все ссылки из чата и отладки. Поиск по базе — на клиенте.

### 3. Виджет `/widget`

Код для вставки, настройки (цвет, сторона, заголовок, приветствие, задержка подсказки, темы страниц) с живым
превью и кнопка «Открыть сайт МТС со встроенным виджетом». Под превью — выбор страницы («Главная» или префикс
из тем): виджет в превью видит этот путь и здоровается по теме страницы.

### 4. Чат в виджете `/embed`

Компактный чат без отладки: приветствие, стартовые вопросы, история в `localStorage`, форма заявки,
кнопка «Новый диалог», ссылки на источники уходят в `/kb` в новой вкладке. На странице с темой (`data-topics`)
приветствие и стартовые вопросы — по продукту страницы, без темы — общие.

## Протокол встраивания

```html
<script src="https://<хост>/widget.js" async
        data-title="Консультант EnergyTool" data-color="#FF0032" data-position="right"
        data-greeting="Подберу решение по энергоучёту и солнечной генерации" data-greeting-delay="6"></script>
```

- `data-quick="Вопрос 1|Вопрос 2"` — быстрые вопросы в подсказке у кнопки (до трёх; по умолчанию два про расходы и
  солнечную станцию, `data-quick=""` — без них). Клик открывает чат и сразу задаёт вопрос.
- Загрузчик создаёт кнопку-лаунчер и `iframe` на `/embed` (стили сайта и виджета изолированы друг от друга),
  на мобильных — на весь экран; Esc закрывает.
- `postMessage` с точным `targetOrigin` в обе стороны; получатель проверяет и `event.origin`, и `event.source`
  (загрузчик — origin `widget.js` и окно своего iframe, `/embed` — origin из `?parent=` и `window.parent`):
  iframe → страница `eb:ready`, `eb:close`, `eb:unread`; страница → iframe `eb:open`, `eb:ask`, `eb:page`
  (`{page, topic, stream}`).
  Сообщения до `eb:ready` загрузчик копит в очереди.
- `iframe allow="clipboard-write; microphone"` — копирование ответа и голосовой ввод в поле вопроса. Если сайт
  сам запрещает микрофон заголовком `Permissions-Policy`, кнопка микрофона в чате просто не получит доступ.
- JS-API на странице: `EnergyToolChat.open()`, `.close()`, `.toggle()`, `.ask("вопрос")` — например, кнопка
  «Спросить консультанта» в карточке продукта открывает виджет с готовым вопросом.

### Потоковая выдача (T13)

```html
<script src="https://<хост>/widget.js" async data-stream="0"></script>
```

- По умолчанию ответ печатается по мере генерации: ядро шлёт события `delta {text}`, Go-API пересылает их как
  есть, чат копит текст в незавершённом сообщении (в `localStorage` он не пишется) и показывает его в том же виде,
  что готовый ответ (`tidyStream` в `src/lib/stream-text.ts` повторяет чистку ядра), с мигающей кареткой.
- Проверка ответа (guard) работает после генерации. Финальное событие `answer` главнее дельт: его текст заменяет
  напечатанный, а если он отличается (ядро ставит `revised: true`), под ответом — метка «Уточнено проверкой»
  с подсказкой. Ответ без дельт (запасной, уточнение ниже порога, сервер модели без потоков) приходит целиком.
- `data-stream="0"` (`false`, `off`, `no`) — потоковую выдачу в виджете выключить: ответ появляется целиком, уже
  проверенный. Флаг — как тема: в адресе iframe (`?stream=0`, верно с первого кадра) и полем `stream` в `eb:page`.
  Стенд печатает всегда; ядро — выключатель `EB_STREAM=0`, режим `eval` не стримит никогда.

### Страница и темы (T8)

```html
<script src="https://<хост>/widget.js" async data-topics='{"/solar":"solar","/askue":"askue"}'></script>
```

- `data-topics` — JSON «префикс пути → тема». Совпадение по границе сегмента (`/solar` подходит к `/solar/roof`,
  но не к `/solarium`), без учёта регистра, побеждает самый длинный префикс, `/` — тема всего сайта. Неверный JSON,
  префикс или имя темы молча пропускаются — тогда общее приветствие. Разбор и сопоставление — чистый модуль
  `src/lib/page-context.ts` (общий для загрузчика и `/embed`, тесты — `npm test`).
- Темы и их тексты — `src/components/chat/topics.ts`, по продуктам базы (`00-reference/00-product-map.md`):
  `solar` — солнечные станции, `askue` — платформа учёта, `losses` — поиск потерь, `orem` — оптовый рынок,
  `tariffs` — ценовые категории, `meter-reading` — показания по фото. Приветствие пересказывает только факты
  документа продукта, вопросы — свои формулировки. Тема меняет только приветствие и стартовые вопросы в чате;
  подсказка у кнопки остаётся из `data-greeting` / `data-quick`.
- **Что передаётся.** Загрузчик шлёт в iframe `eb:page {page, topic}`: `page` — `path` (`location.pathname`),
  `title` (`document.title`) и только пять UTM-меток (`utm_source|medium|campaign|term|content` из
  `location.search`); каждое значение до 300 знаков, объект до 2 КБ. Тема — ещё и в адресе iframe (`?topic=`),
  чтобы приветствие было верным с первого кадра. Страница отправляется при создании iframe и при каждом открытии
  чата — на сайтах-SPA путь меняется без перезагрузки виджета.
- **Что не передаётся.** Cookies, полный адрес и любые другие параметры строки запроса (`gclid`, `email`, id
  сессий сайта), `referrer`, `localStorage` сайта. Путь, заголовок и метки не попадают в адрес iframe — только
  в сообщение. `/embed` не верит сообщению: заново оставляет известные поля, строки и пределы.
- **Куда идёт.** Чат кладёт `page` в тело `POST /api/chat` вместе с `session_id`; Go-API строго проверяет
  (объект, ≤ 2 КБ, ключи `path`, `title`, `utm_*` из списка, строки ≤ 300 знаков — иначе 400) и пишет в
  `sessions.page`: при создании сессии и заново, если пришла непустая. Это аналитика для менеджера (T6).
  **Ядру и в промпт страница не уходит** — ответ строится только по репликам клиента и базе знаний.
- **Будущая опция — `EB_PAGE_BOOST`** (не сделано): тема страницы как подсказка поиску — небольшой буст
  разделов документа продукта страницы, не факт в промпте. Выключен по умолчанию; включать только после замера
  `eval/retrieval_eval.py --split dev` «до/после», если доля разделов эталона в контексте не падает.

## API (`backend/`, через Next — `/api/*`)

| Метод | Ответ |
|---|---|
| `GET /api/health` | схема, модель, эмбеддинги, реранкер, число документов/разделов |
| `GET /api/kb` | документы → разделы `{id, path, text, links, is_guard, is_reference}` |
| `POST /api/chat` `{messages, mode, session_id?, channel?, page?}` | SSE: `stage` (retrieval: hits, queries, context), `stage` (generation), `answer` (text, sources, citations, guard, timings, prompt), `done` |
| `POST /api/lead` | резюме диалога для менеджера (LLM, при сбое — список вопросов клиента), запись в Postgres (`leads`) |
| `POST /api/feedback` | 👍/👎 с комментарием → Postgres (`feedback`) |
| `GET /api/settings`, `POST /api/settings`, `POST /api/settings/reset` | настройки RAG ядра: прочитать, сохранить глобально (до перезапуска ядра), вернуть из окружения |

| Продукт | Что у них есть | Что берём |

| Chatbase, Voiceflow, Botpress | конструктор виджета с превью, код вставки одной строкой, журнал диалогов | страница `/widget` с настройками и превью |
| Dify, RAGFlow | «тест поиска» по базе, просмотр нарезки на чанки с подсветкой | вкладка «Поиск», `/kb` с нарезкой как у модели |

Дальше (не в этом шаге): журнал диалогов и заявок для менеджера, сравнение двух вариантов бота бок о бок
(A/B, как в eval/lab.py), стриминг токенов, голосовой ввод, авторизация админки.

## Запуск

```bash
docker compose up --build                     # база, ядро и API: http://127.0.0.1:8787 (читает .env)
cd web && npm install && npm run dev          # стенд: http://localhost:3000
node web/scripts/stand.mjs --site <папка energytool.mts.ru>   # сайт МТС с виджетом: http://localhost:4000
```

# Визуальная система

Записано по собранному стенду (ноябрь 2026). Токены — во frontmatter выше и в `src/app/globals.css`;
расширения (тени, движение, брейкпоинты, компоненты) — в `.impeccable/design.json`.

## Overview

Каркас как в приложениях Claude и ChatGPT: одна боковая панель (навигация, история или дерево базы, статус API,
тема), широкая центральная колонка разговора, инструменты — в соседней панели. Нейтрали — графит и холодные
серые МТС, красный `#FF0032` работает только там, где действие или опора: отправить, главная кнопка, номера
источников, выбранный раздел базы. Сигнатура — красные номера источников после предложений и строка
источников под ответом: клик ведёт ровно в тот раздел базы, который видела модель.

## Colors

- Светлая тема: лист `#ffffff`, текст `#1d2023`, сайдбар и второй слой `#f7f8fa`, заливки `#f2f3f7`,
  вторичный текст `#626c77` (≥4,8:1 на заливках), линии `#e4e6eb`.
- Тёмная тема: основа — графит МТС `#1d2023`, сайдбар глубже `#17191c`, всплывающие слои `#26292d`,
  текст `#eceef1`, вторичный `#9ba3ad`. **Сейчас выключена** (решение владельца, ноябрь 2026): стенд принудительно
  светлый, переключателя нет; токены `.dark` сохранены, включается флагом `LIGHT_ONLY` в `theme-provider.tsx`.
- Красный мягкий, не кислотный (ноябрь 2026): `brand #d0424a` — заливка знака и кнопки «Отправить» (белая иконка, контраст 4,6:1; в тёмной `#e60030`, 4,8:1);
  `primary #cc3d44` — кнопки с белым текстом (контраст 4,9:1); `brand-text #c23a41` — красный текст и номера
  источников (`#ff5c76` в тёмной). Мягкая подложка — `brand-soft`. Виджет на чужом сайте берёт цвет из `data-color`.
- **Доступность (T43, WCAG 2.2 AA).** Текст ≥4,5:1 в обеих темах, в том числе на мягких подложках (`success-soft`,
  `destructive-soft` подобраны под это) и у плейсхолдеров; серый подписной текст — `muted-foreground` без
  прозрачности (`/70`, `/80` давали ~3,6:1). Лента сообщений — `role="log"` с `aria-live="polite"` и `aria-busy`
  на время генерации: ответ озвучивается целиком; фокус остаётся в поле ввода; Esc в виджете сворачивает чат и
  возвращает фокус на лаунчер. На экранах до 640 px цели касания ≥44 px (`max-sm:size-11`),
  `prefers-reduced-motion` гасит все анимации. Проверка в CI: `npm run test:a11y` (Playwright + axe).
- **Без полупрозрачности и бледных подложек.** Метки, статусы, номера источников и иконки-плашки — сплошная
  насыщенная заливка с белым текстом: номера источников и плашки разделов — `primary`, статусы — `tone-success /
  tone-warning / tone-info / tone-danger` (контраст с белым ≥4,5:1, свои значения в тёмной теме). Подсветка
  найденного и выделение текста — `primary` с белым текстом. Раздел базы по ссылке — сплошной `surface` с тонкой
  красной обводкой. Фон полей — `field`, приглушённые точки и дорожки — `dim`. Полупрозрачным остаётся только
  затемнение под открытым диалогом и листом — сплошное спрятало бы страницу, с которой человек пришёл.
- Состояния: `success` (опора найдена, заявка передана, полосы совпадения в отладке — единственный цвет данных
  помимо `info`), `warning` (запасной ответ, ограничения), `destructive` (числа без опоры, ошибки),
  `info` (раздел в контексте модели). Этапы времени ответа — `chart-1…4`.
- Виджет на чужом сайте всегда светлый (`/embed` принудительно в светлой теме); цвет из `data-color`
  подменяет `--brand`, `--primary`, `--brand-text`, `--brand-soft`.

## Typography

Onest (кириллица в основе гарнитуры) — весь интерфейс; JetBrains Mono — только код, id разделов, промпт,
JSON, имя модели. Шкала фиксированная, в px: 40 / 34 на мобильных (заголовок /widget) / 32 (пустой чат) / 30 (документ базы) / 28 (заголовок страницы) / 24 (раздел страницы) /
22 (итог опоры) / 19 (диалог) / 18 (раздел базы) / 16 (вступление документа) / 15 (текст ответа, 1,7) /
14 (интерфейс) / 13 (вторичный) / 12 (подписи) / 11 (моноширинные номера и скоры) / 10,5 (номера источников). Цифры в таймингах, скорах и счётчиках — `tabular-nums` (класс `.tnum`).

## Layout

- Сайдбар 264px, как в Claude: знак и кнопка сворачивания; «Новый диалог» с красным кружком «+»; «Поиск» — обычный
  пункт, по клику становится полем; разделы стенда; плоский список «Недавние» (сворачивается по заголовку, «…» у строки,
  спиннер у диалога, где идёт ответ); внизу на месте аккаунта — строка «Стенд EnergyTool» с моделью и статусом API,
  по клику — сводка о модели, поиске и базе. На экранах <1024px — выезжающая панель с кнопкой-меню; на широких
  сворачивается кнопкой, состояние хранится в `localStorage`.
- Заголовок диалога в верхней строке — кнопка с «⌄»: переименовать, экспорт Markdown/JSON, удалить.
- Верхняя строка рабочей области — 56px: заголовок слева, действия справа.
- Колонка чата и документа базы — 720px. Пустой чат: знак, вопрос «Чем помочь с электроэнергией?»,
  поле ввода и подсказки по центру.
- Отладка — правая панель (≈40%, тянется) на ≥1024px, выезжающий лист на узких; открывается кнопкой
  «Показать в отладке» под ответом.

## Elevation & Depth

Плоско: волосяные линии и смена слоя (`background` → `surface`). Тень только у поля ввода
(`--shadow-float`) и у всплывающих слоёв: диалог, лист, меню, превью источника (`--shadow-pop`).
Затемнение под диалогом — графит 42% (тёмная тема — чёрный 60%), без размытия.

## Shapes

Радиусы: 6 (метки), 10 (кнопки, поля, пункты сайдбара), 14–18 (блоки отладки, диалог), 24 (сообщение
клиента), 26 (поле ввода), круг (кнопка отправки, чипы источников, переключатель темы).

## Components

- **Сообщения.** Клиент — серая плашка справа; ответ бота — плоский текст без пузыря и аватара, под ним строка
  источников и действия (копировать, ответить заново, 👍/👎, отладка, время ответа, метки проверки).
- **Строка «думает»** (пока идёт ответ) — как в Claude: знак EnergyTool, у которого стрелка прибора ходит по шкале,
  фраза с бегущим бликом и секундомер с 2 с. Фразы следуют настоящим этапам потока: поиск («Ищу в базе знаний»…) →
  найденные разделы («Читаю 15 разделов из 3 документов», под строкой — названия документов) → генерация
  («Формулирую ответ», «Сверяю цифры с базой знаний»…). Внутри этапа фраза меняется раз в 2,8 с и мягко всплывает,
  на последней останавливается. Смена строго по очереди: старая гаснет (200 мс), потом проявляется новая — две фразы
  разом не видны; ширина строки едет к новой фразе. Готовый ответ проявляется на её месте. При
  `prefers-reduced-motion` — статичный текст.
- **Поле ввода.** Скруглённое 26px, внизу подсказка клавиш и круглая кнопка: серая, пока пусто; красная,
  когда можно отправить; графитовая «стоп» во время ответа.
- **Знак** — красная плашка со шкалой прибора учёта и стрелкой (не логотип МТС); рядом одной строкой
  «EnergyTool AI» (AI — красным).
- **Пустой чат** — как в Claude: знак без плашки и вопрос одной строкой (30px, medium), под ним одна тихая строка
  о том, откуда ответы; поле ввода; под ним тонкие серые пилюли подсказок (полный вопрос — в подсказке и уходит при клике).
- **Источники под ответом** — свёрнутая кнопка «стопка номеров · N источников · M документа», по клику — список
  «раздел / документ», каждая строка открывает раздел базы.
- **Отладка** — нейтральная, как правая панель Claude Code: цвет только у проблем (числа без опоры, предупреждения —
  мягкие подложки), всё остальное графит и серые: полосы совпадения и итог опоры — оттенки графита, найденные числа —
  серые метки, активная вкладка — графитовая линия, заголовки секций — приглушённые. Фон как у листа, без карточек в карточках: шапка строками «иконка — значение» (вопрос клиента,
  модель, время · режим, метки проверки), списки разделены волосяными линиями во всю ширину панели; вкладки-подчёркивания
  со счётчиками (активная — красной линией). «Опора»: итог «опираются / всего», полоса статусов по предложениям,
  у каждого предложения значок статуса и разделы с процентом совпадения (зелёный ≥50%, янтарный ≥30%) и
  найденными числами. «Поиск»: запрос, фильтр «Все / В контексте / Отброшены», ранжированный список с точкой
  статуса и скором. «Контекст»: три числа в одной полосе, документы целиком, фрагменты, все разделы по документам.
- **База знаний** — дерево в сайдбаре 300px: номер документа из имени файла (00, 23…) моноширинным, название
  в одну строку, у открытого документа — разделы на тонкой линии, текущий отмечен красной линией. Шапка документа:
  крупный номер файла красным моноширинным (56px) рядом с заголовком 32px; под ними полоса между волосяными линиями —
  группа и место в ней («4 из 7»), число разделов, время чтения, путь файла (клик копирует). Разделы нумеруются как
  главы — 23.1, 23.2… — номер на полях слева (≥1280px) копирует ссылку на раздел, те же номера в оглавлении;
  строки «Ключ: значение; Ключ: значение» показываются таблицей, одиночные пары — списком «ключ — значение».
  Справа на ≥1280px — оглавление «На странице» с подсветкой текущего раздела.
- **Диалог заявки** — 460px, заголовок 19px, карточка «что увидит менеджер», поля 40px с проверкой при уходе
  из поля, «Отмена» + красная «Отправить заявку»; успех — зелёная галочка и резюме для менеджера.
- **Лаунчер виджета** — красный круг 56px; подсказка 304px: знак, название, статус «Отвечает по базе знаний МТС»,
  приветствие и быстрые вопросы-кнопки; панель 400×680 с радиусом 20px, на мобильных — во весь экран.
- **Ответы в виджете** — чистый текст без номеров и строки источников (они для жюри на стенде). Над полем ввода —
  строка во всю его ширину «Передать запрос менеджеру» с иконкой и подписью; после отправки — «Заявка передана».
- **Номера источников** — скруглённые квадраты (радиус 5–6px), не круги: в тексте, в стопке под ответом, в отладке.
- **Фигура на /widget** — справа от заголовка: плитка 280px с радиусом 48px, в ней шкала прибора учёта (знак
  EnergyTool крупно) — дорожка, красная зона и деления в цвете из настроек, стрелка при загрузке уходит в красную
  зону, в центре «1 строка кода»; поверх — уменьшенные подсказка и кнопка виджета с текущими заголовком,
  приветствием, первым быстрым вопросом и цветом.
- **Страница /widget** — заголовок в два тона («Консультант на любом сайте — / одной строкой.») и под ним та самая
  строка `<script …>` с подсветкой синтаксиса и копированием полного тега. Слева — карточка настроек: «Внешний вид»
  (заголовок со счётчиком, цвета + свой цвет пипеткой + HEX, сторона экрана схемой) и «Подсказка у кнопки»
  (приветствие со счётчиком, быстрые вопросы списком до трёх, задержка ползунком). Справа — превью в окне браузера
  с адресной строкой: копия сайта МТС со стенда (`stand.js` принимает `?w_title=&w_color=&w_position=&w_greeting=
  &w_greetingDelay=&w_quick=&w_topics=&w_path=&w_preview=1`) или пустая страница `public/widget-preview.html`
  (те же ключи без `w_`); «Компьютер / Телефон»; «Спросить в превью» шлёт `postMessage({type:"eb:preview"})` —
  стенд принимает его только с origin виджета. Третий раздел настроек — «Темы страниц»: строки «префикс пути
  (моноширинный) → тема (список)», до восьми. Под превью — «Страница: Главная / префиксы» и подпись, какая тема
  включится; путь превью подменяется через `history.replaceState` и виден в адресной строке.
- **Верхняя строка страниц** — плашка с иконкой раздела, заголовок 15px полужирный и приглушённое пояснение.
- **Настройки RAG `/settings`** — как настройки Claude Code: колонка 680px, вступительная строка (действуют для всех
  со следующего вопроса, сколько отличается от окружения), разделы «Поиск», «Генерация», «Модель» с приглушёнными
  заголовками, строки на волосяных линиях: название 14px, пояснение 13px, имя переменной окружения моноширинным;
  справа переключатель, поле 96px или список. Изменённая строка — красная точка у названия; отличающаяся от окружения —
  «в окружении: N · вернуть». В шапке «Сбросить к окружению» и «Сохранить»; пока есть несохранённое — плавающая
  плашка снизу «Не сохранено: N · Отменить · Сохранить». Пределы проверяются на месте, ошибка — под строкой.
- **Заявка в виджете** — не модалка поверх окна, а отдельный экран: шапка с «назад», форма в одну колонку,
  красная кнопка во всю ширину внизу; после отправки — резюме для менеджера парами «поле — значение».

## Do's and Don'ts

- Do: красный — только действие, источник, выбранный раздел. Всё остальное — графит и серые.
- Do: новые экраны собирать из `AppShell` + `PageBar` + сайдбара с контекстным списком.
- Do: проверять обе темы; числа в данных — `.tnum`, код и id — моноширинным.
- Don't: карточки в карточках, плитки «иконка + заголовок + текст», надписи-кикеры над заголовками.
- Don't: сырые цвета Tailwind (`sky-500`, `emerald-600`…) — только токены `success / warning / info / destructive`.
- Don't: тёмная тема в `/embed` — виджет живёт на светлом сайте клиента.
