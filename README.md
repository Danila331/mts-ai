# ИИ-консультант МТС EnergyTool

Решение кейса **«МТС EnergyTool: ИИ-консультант для сайта»** (МТС True Tech Hack&Change 2026).

Бот на сайте понимает задачу клиента, уточняет недостающее и отвечает **только по базе знаний** (с номером
источника у каждого факта). Когда задача ясна, он сам предлагает передать разговор менеджеру. Менеджер
получает заявку с паспортом задачи, оценкой, резюме и всей перепиской.

**Стенд:** https://energytool-ai.vercel.app

> Репозиторий приватный: базу знаний по правилам кейса публиковать нельзя. Доступ жюри — аккаунт `hack-and-change-2026`.

## Запуск одной командой

Нужен Docker с Compose v2. Из корня репозитория:

```bash
cp .env.example .env && docker compose up --build
```

Откройте http://localhost:3000.

- **Ключ модели.** Чтобы бот отвечал по-настоящему, впишите в `.env` `LLM_BASE_URL` и `LLM_API_KEY` (любой
  OpenAI-совместимый API, модель по умолчанию — `qwen/qwen3.8-27b`). Без ключа всё запустится, но вместо
  ответов будет заглушка.
- **Первый старт** занимает несколько минут: ядро считает эмбеддинги базы. Готовность служб покажет
  `docker compose ps` — все должны быть `healthy`.
- **Остановить:** `docker compose down`. Вместе с данными: `docker compose down -v`.

| Что | Адрес |
|---|---|
| Стенд: чат, виджет, менеджер | http://localhost:3000 |
| API | http://localhost:8787 |
| Grafana — дашборды (`admin` / `dev-grafana-local`) | http://localhost:3001 |
| Prometheus | http://localhost:9090 |

## Что посмотреть (5 минут)

1. **Чат** (`/playground`). Спросите: «Нужен учёт электроэнергии на складе, с чего начать?» Бот ответит и уточнит
   задачу. Номера после предложений — источники: клик открывает раздел базы с подсвеченной строкой. Справа —
   «Разбор ответа»: поиск, контекст, промпт, уверенность.
2. **Передача менеджеру.** Со второй реплики (и сразу, если спросить о цене) бот сам предлагает «Передать
   менеджеру». Форма заполнится из чата; используйте тестовые данные «Тестов Тест Тестович», `+7 900 000-00-00`,
   «ООО Учебный склад».
3. **Менеджер** (`/manager`, без входа). Вкладки:
   - «Заявки» — оценка, паспорт задачи, резюме, шпаргалка к звонку;
   - «Диалоги» — все разговоры, в том числе без заявки;
   - «Аналитика»;
   - «Копилот».
4. **Виджет** (`/widget`). Код вставки одной строкой и живое превью на копии сайта МТС.
5. **Ещё:**
   - «База знаний» (`/kb`);
   - «Проверить выгрузку» (`/check-data`);
   - «Настройки RAG» (`/settings`) — песочница, свои настройки только для своих ответов.

Проверка связности всех служб одной командой (её же запускает CI):

```bash
sh backend/scripts/smoke.sh http://127.0.0.1:8787 "$EB_API_TOKEN" http://127.0.0.1:3000
```

## Как устроено

```
браузер ──▶ web (Next) ──/api/*──▶ api (Go) ──▶ core (Python, energybot/) ──▶ llm-gateway (LiteLLM) ──▶ модель
            стенд, виджет            │ сессии, заявки, менеджер
                                     ├──▶ Postgres   ├──▶ Redis (пределы частоты)
                                     └──▶ Prometheus ──▶ Grafana
```

- Браузер ходит только в `web`: адрес и токен API знает сервер Next.
- Ключ модели знает только шлюз `llm-gateway`.
- Ответы строит то же ядро `energybot/`, что и решение для автопроверки.

## Где что лежит

| Путь | Что там |
|---|---|
| `web/` | стенд и виджет (Next.js, React) |
| `backend/` | API на Go: чат (SSE), сессии и переписка, паспорт задачи, заявки и их оценка, экран менеджера |
| `energybot/` | ядро RAG: поиск, промпты, проверка чисел — общее для стенда и автопроверки |
| `scripts/core_api.py` | HTTP-сервер ядра для стенда; рядом — правила чата (предложение менеджера, «честное нет», быстрые ответы) |
| `solution.py` | точка входа автопроверки (сабмит) |
| `knowledge-base/` | база знаний — единственный источник фактов |
| `llm-gateway/`, `monitoring/` | шлюз к моделям; Prometheus и Grafana |
| `eval/`, `tests/` | проверочная выборка (~500 кейсов), слепой судья; тесты |
| `docs/` | развёртывание, архитектура (C4, ADR), приватность, защита, роадмап |
| `МТС_кейс.pdf`, `docs/tech-regulations.md` | условие кейса и регламент организаторов |

## Сабмит для автопроверки

```bash
uv venv -p 3.11 .venv && uv pip install -p .venv/bin/python httpx==0.28.1 numpy==2.2.6
.venv/bin/python scripts/build_submission.py --final   # → dist/submission-final.zip
.venv/bin/python scripts/check_submission.py --final   # сверка с регламентом
```

Итоговый сабмит — [`submissions/final/`](submissions/final/README.md).

## Проверки

```bash
.venv/bin/python -m unittest discover -s tests       # Python, без ключей
make -C backend lint test                            # Go
cd web && npm ci && npm run lint && npm test         # веб; браузерные тесты — npx playwright test
```

Всё это и сборку образов со сквозным прогоном `docker compose` CI запускает на каждый PR.

## Ограничения

- Факты, цены и пороги — только из базы знаний. Расчётов в рублях бот не делает, время звонка и сроки не обещает.
- На стенде только тестовые персональные данные. Экран менеджера — демо без входа.
- Фото документов распознаются, только если задана vision-модель (`EB_VISION_MODEL`).

## Git Flow

Работа ведётся от `dev` в отдельных ветках. В `main` (прод: Vercel и Railway выкатывают его автоматически) —
только через PR из `dev`. Подробно — `AGENTS.md`.
