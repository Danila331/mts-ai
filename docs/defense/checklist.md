# Чек-лист страховки перед защитой

Пункты из T42 (`docs/ROADMAP.md`): видео, QR-код, проверенный набор запросов, интернет с телефона, первый слайд.
Ответственные — роли из [`QA.md`](QA.md), имена вписывает команда.

## Риски, которые надо закрыть заранее

- **Стенд может не совпадать с веткой.** Vercel и Railway выкатывают только `main` (`docs/deploy.md`). На момент
  написания T28 (`compose.yaml`, сервис `web`) и T29 (песочница `/settings`) были в `integration/waves-0-3`, но не в
  `origin/main`. Пока T29 не выкачен, `/settings` на стенде меняет бота для всех посетителей, а метки «ответ с
  вашими настройками» нет. Проверка:
  `git fetch && git merge-base --is-ancestor 21a9f77 origin/main && echo "T29 в main"`.
  Если T29 не в `main`, `/settings` на боевом стенде не показываем и показываем песочницу на локальном стенде.
- **Пределы частоты считаются по адресу.** 20 вопросов в минуту (всплеск 5), 10 заявок в час (всплеск 3),
  10 запросов к настройкам в минуту (`docs/deploy.md`, «Переменные API»). Если жюри сканирует QR из того же Wi-Fi,
  что и мы, все за одним NAT делят лимит. Репетиции заявок в последний час — не больше двух, иначе на сцене
  получим 429.
- **Холодный старт ядра.** После перезапуска ядро считает эмбеддинги базы минуты (healthcheck на Railway — 300 с).
  Без модели оно отвечает по BM25 и достраивает векторы в фоне. Стенд прогреваем вопросом заранее.
- **Ответ без потоковой выдачи** приходит целиком (T13). Паузу заполняем комментарием, повторно не жмём.
- **Без ключа модели** локальный стенд отвечает заглушкой. Проверить `.env` у ноутбука с запасным стендом.

## Первый слайд (по кейсу)

- Название: «ИИ-консультант МТС EnergyTool», команда, кейс Hack&Change 2026.
- **Развёрнутый интерфейс:** https://energytool-ai.vercel.app + QR-код.
- **Репозиторий:** `Danila331/mts-ai` (GitHub, приватный; доступ выдан аккаунту `hack-and-change-2026`). Полную
  ссылку вставить с GitHub, проверить из чужого аккаунта, что открывается.
- **Порядок проверки** (README, «Что посмотреть (5 минут)»):
  1. `/playground` → вопрос «Нужен учёт электроэнергии на складе, с чего начать?» → уточняющий вопрос бота.
  2. Ответ на уточнение → номера источников → клик → раздел базы `/kb?chunk=<id>`.
  3. «Отладка ответа»: Опора, Поиск, Контекст, Промпт, Проверка, JSON.
  4. «Передать запрос менеджеру» → тестовые данные → «Отправить заявку» → номер заявки и резюме.
  5. «Новый диалог» — чистая сессия. `/widget` — код вставки и превью.
  6. Локально: `cp .env.example .env` → `docker compose up --build` → http://localhost:3000.
- Тестовые данные для формы: «Тестов Тест Тестович», `+7 900 000-00-00`, «ООО Учебный склад».
