# 0006. Vision-модель только как OCR перед Qwen

- Статус: **принято, не реализовано** — задача T9 в `docs/ROADMAP.md`, в разделе 6 «не начата». Кода OCR и
  переменной `EB_VISION_MODEL` в репозитории нет.
- Дата решения: 2026-11-15 (решение владельца в `docs/ROADMAP.md`, раздел «Решения владельца»); запись — 2026-11-15

## Контекст и проблема

Сильный сценарий для клиента — загрузить фото или PDF счёта и сразу получить разбор. Модель консультанта —
Qwen3.8-27B, текстовая. Промпт, guard и проверочная выборка подобраны под неё (`energybot/prompts.py`,
`energybot/guard.py`, `eval/`). Факты — только из базы знаний.

## Факторы решения

- Консультирует одна модель с одним промптом и одной проверкой ответа.
- Документ клиента — это данные клиента, а не источник фактов о продуктах.
- Файл с реквизитами клиента — персональные данные: хранить его не нужно.
- Без vision-модели стенд должен работать как сейчас.

## Рассмотренные варианты

1. **Не принимать файлы.**
2. **Мультимодальная модель сама отвечает клиенту** по фото и базе.
3. **Vision-модель только переписывает текст документа, отвечает Qwen.**

## Решение

Вариант 3 (решение владельца, план — T9):

- PDF с текстовым слоем — извлечение текста без модели;
- фото или скан — vision-модель `EB_VISION_MODEL` (OpenAI-совместимый `/chat/completions` с `image_url`) с
  указанием «перепиши текст документа как есть, ничего не добавляй»;
- текст становится частью реплики клиента («Текст из документа: …») и идёт в обычный конвейер Qwen;
- извлечённые поля клиент подтверждает до записи в паспорт;
- файл обрабатывается в памяти и не сохраняется; лимит 10 МБ, типы `pdf/jpg/png/heic`;
- без `EB_VISION_MODEL` фото не принимаются, PDF с текстом работает всегда;
- модуль не попадает в сабмит.

Почему не остальные:

- **Не принимать файлы** — теряем сценарий, которого у конкурентов для юрлиц в РФ не нашли (ROADMAP, раздел 1).
- **Мультимодальная модель отвечает сама** — второй консультант с другим промптом, без проверки на выборке и
  без guard, настроенного под Qwen; база и эталоны подбирались под одну модель.

## Последствия (цена решения)

- Плохо: ещё одна модель и ключ; ошибки распознавания уходят в Qwen как слова клиента.
- Плохо: текст документа — канал непрямой prompt injection. Нужна разметка «данные клиента, не инструкции»
  (spotlighting) — задача T35, не сделана ([threat-model.md](../threat-model.md)).
- Обязательно: текст документа должен попасть в реплики, которые видит `energybot/guard.py`, иначе числа из счёта
  будут считаться выдуманными и вырезаться. Нужен тест (ROADMAP, T9).
- Хорошо: путь ответа и его проверка не меняются; без vision-модели ничего не ломается.

## Замеры

Замера нет: решение не реализовано. План приёмки — 3 синтетических счёта в `tests/fixtures/` (ROADMAP, T9).
